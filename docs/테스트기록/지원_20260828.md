# 테스트 기록 — 지원

로컬(`interview_ai-develop-2`)에서 백엔드 API를 직접 호출해 실제 면접을 5회 완주했다(텍스트 답변, 자동화 스크립트).
8/26~27 공유된 4개 이슈(꼬리질문 중복, 질문 개수 변동, 꼬리질문 오채점, type 오분류)가 재현되는지 확인했다.

```
세트 A   주니어 백엔드(2년 6개월, Spring/JPA/MySQL/Redis) + 백엔드 JD(2~4년, 커머스) + 기술 리드
세트 B   시니어 PM(5년 3개월, 카풀 매칭·A/B테스트·팀 조율) + PM JD(4년 이상, 모빌리티) + 임원 면접관
```

두 세트를 번갈아 등록해서 돌렸다(런1,3,5=A / 런2,4=B). 원본은 `docs/qa/local-test-지원-raw.json`로 남겨뒀다.

## 2. 꼬리질문/주질문 중복 (8/28)

5회 전부에서 최소 1개 이상 근접 중복 쌍이 나왔다.

| 런 | 중복 사례 |
|---|---|
| 1 | #5 ↔ #6 "병목 식별 시 (우선) 확인할 지표와 임계값" |
| 2 | #2/#3 "매출·운영비 영향" / #5/#6 "A/B 테스트 하나 골라 가설" |
| 3 | #5 ↔ #6 "요청량 10배 시 (우선) 확인할 지표" |
| 4 | #5/#6 "매칭성공률 개선 인과관계" / #8/#9 "A/B 테스트 임팩트" / #14/#15 "PM 역량 개발 계획" 3연속 |
| 5 | #2 ↔ #3 "예상 트래픽 / 피크 초당 요청 수" |

### 관찰

**"A/B 테스트 하나 골라서 가설 설명해달라"는 PM 페르소나 4번(런2, 4) 전부에서 나왔다.** 우연이 아니라 이 이력서/JD 조합에서 안정적으로 재현되는 패턴으로 보인다.

```
원인   follow_up_generator.py 가 꼬리질문을 만들 때 최근 4개 메시지만 참고
       (state["messages"][-4:]) → 방금 전 질문·답변과 비슷한 내용을 다시 생성
```

## 3. 꼬리질문 오채점 (구조상 5/5)

`answer_evaluator.py`가 채점 LLM에 넘기는 `question` / `good_answer_criteria`는 항상 `question_list[current_question_index]`(주질문)이다. 꼬리질문에 답해도 채점 기준은 항상 주질문 것이 쓰인다.

화면에 보이는 질문 텍스트는 실제 꼬리질문이 맞다. **채점 시 LLM에 전달되는 기준만 주질문 것이라는 게 문제.**

## 4. type 오분류 (5회 중 3회)

| 런 | 사례 |
|---|---|
| 2 | #11 "팀 갈등 중재" 꼬리질문인데 내용은 "우선순위 판단 근거"로 회귀 / #15 "SQL 데이터 추출" 꼬리질문인데 내용은 "A/B 테스트"로 이탈 |
| 4 | #11 "팀 충돌" 꼬리질문인데 내용은 "신규 기능 우선순위 판단 근거"로 이탈 |
| 5 | #9 "재고 조회 API 성능개선" 꼬리질문인데 내용은 "배치 스크립트 재시도"로 이탈 |

`question_type`(`follow_up`/`next`/`end`)은 `follow_up_count > 0` 여부로 기계적으로 정확히 매겨진다. **꼬리질문이 실제로 직전 주제를 파고드는 내용인지는 보장하지 않는다.**

## 5. 질문 개수 재현 시도 (0/5)

5회 전부 정확히 6개(라포 1 + 평가 5)가 나왔다.

**재현되지 않았다.** `question_generator.py`에는 LLM이 반환한 질문 개수를 검증하는 코드가 없어서, 팀에서 본 "10회 중 2회" 문제는 구조적으로 여전히 가능해 보인다. 표본 5개로는 못 걸렸을 수 있다.

## 6. "14 vs 15" 리포트 경고 (8/28)

면접이 끝날 때마다 서버 콘솔에 같은 경고가 남았다.

```
실시간 점수 14개와 리포트 피드백 15개가 맞지 않아 점수를 그대로 둡니다
```

`backend2_8002.log`에서 session_id로 대조했다.

```
run1 6c7472fb...  run2 ef67c1e5...  run3 061c6f53...
run4 552dacdf...  run5 a0e5e629...
```

**5회 전부에서 확인됐다.** 실제 평가 질문은 15개인데 실시간 점수는 14개만 집계되는 것으로 보인다. 라포 질문 카운트 방식 차이이거나 마지막 문항 처리 타이밍 문제로 추정. 원인은 더 봐야 하지만 100% 재현이라 우선순위 있게 봐도 좋을 것 같다.
