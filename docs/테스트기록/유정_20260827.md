## 2. 경력 단계별 이력서 비교 (8/26)

같은 채용공고로 이력서만 바꿔 면접 시작까지 돌렸다.

| 이력서 | 매칭 점수 | 질문 수 | 누락 스킬 |
|---|---|---|---|
| 신입 | 65 | 6 | 4개 (쿼리 최적화 · Redis · Docker · 대규모 트래픽) |
| 주니어 (2년 9개월) | 88 | **5** | 없음 |
| 미들 (5년) | **95** | 6 | 없음 |
| 시니어 (9년) | 92 | 6 | 2개 (쿼리 최적화 · Docker) |

### 관찰

**미들이 가장 낫다.** 매칭 95, 누락 없음, 이력서 문구를 그대로 인용한 질문이 나온다.

```
p95를 940ms에서 180ms로 개선하셨다 했는데 어떤 순서로 무엇을 변경하셨는지
결제 재시도를 배치에서 Kafka 기반 큐로 전환하셨다 했는데 멱등성은 어떻게
코드 리뷰 문화를 정착시키셨다 했는데 어떤 규칙과 도구를 도입하셨고
```

**신입** — 이력서에 없는 걸 묻는 질문이 섞인다. `가상의 시나리오로 설명해 주시겠어요?`

**주니어** — 질문이 5개만 나왔다(라포 1 + 평가 4). 그리고 `type=인성` 인데 내용은
API 문서화인 질문이 있었다.

**시니어** — 이력서에 Docker · 쿼리 최적화 표현이 없어서 누락으로 잡혔다.
테스트 이력서를 만들 때 빠뜨린 것이라 제품 문제는 아니다.

## 3. 전체 면접 3회 (8/27)

미들 이력서로 답변 수준만 바꿔가며 끝까지 돌렸다.

| 회차 | 답변 조건 | 평균 점수 | 등급 | 답변 턴 | 총 소요 |
|---|---|---|---|---|---|
| 1차 | 준비한 답변을 순서대로 (질문과 불일치) | 58.8 | C | 13 | 8.6분 |
| 2차 | 질문 키워드에 맞는 답변 | 62.1 | B | 12 | 5.5분 |
| 3차 | 수치 · 판단 근거 · 대안 비교 포함 | **72.3** | **B+** | **8** | 5.3분 |

### 3차 상세

```
면접 시작      46.2초
답변 처리      15~45초, 평균 34.3초
리포트 생성    122.3초
70점 이상      4 / 7
```

### 관찰

**70점을 넘기면 꼬리질문이 붙지 않는다.** 그래서 13턴이 8턴으로 줄었다.

채점 기준이 `70~89점: 구체적인 경험과 근거를 포함한 좋은 답변` 이라, 수치와 판단
근거가 없으면 60점대에 머문다. 답변이 부실해서가 아니라 기준이 그렇다.

답변 작성 시간을 턴당 1분으로 잡으면 전체 13~15분이다. 30분 제한 안에 들어간다.

## 5. 질문 개수 재현 (8/26)

프롬프트는 6개(라포 1 + 평가 5)를 지시한다.

| 실행 | 입력 | 결과 |
|---|---|---|
| 재현 3회 | 임의 이력서 | 6개 · 6개 · 6개 |
| 재현 3회 | 스모크 테스트와 동일 입력 | 6개 · 6개 · 6개 |

**재현되지 않았다.** 스모크 테스트에서 7개가 나온 것과 경력별 비교에서 주니어가
5개 나온 것을 합치면 10회 중 2회가 지시와 다르다.

## 6. reasoning_effort 비교 (8/24)

같은 프롬프트로 질문 생성만 5회씩 돌렸다.

| 설정 | 평균 시간 | 한 질문에 요청 3개 이상 |
|---|---|---|
| medium | 36.3초 | 0 / 30 |
| low | 16.9초 | 1 / 30 |

low 에서 걸린 질문

```
실제 쿼리 튜닝 사례 하나를 설명해 주시겠어요 원래 쿼리 문제는 무엇이었고
어떤 인덱스나 리팩토링을 적용하셨나요 성능이 어떻게 바뀌었나요?
```

**질문 생성은 medium 을 유지하기로 했다.** 8/20 실행에서도 low 에서 같은 형태가 나왔다.

원본은 `reasoning_effort_비교_20260824.txt` 로 남겨뒀다.
